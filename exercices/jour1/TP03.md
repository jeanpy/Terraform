# TP 03 — Configurer Cloud-Init et SSH sur Proxmox

> **J1 · Durée : 75 min · Modalité :** manipulation individuelle ou binôme · **Public :** Administrateur Cloud DevOps

## Situation professionnelle

Vous intervenez dans une équipe infrastructure qui souhaite rendre les déploiements reproductibles, contrôlables et documentés. Chaque changement doit être réalisé via l'Infrastructure as Code, sous réserve des prérequis et des permissions du laboratoire.

## Objectif opérationnel

Configurer un compte Linux, la clé SSH et l’adressage IP initial.

## Prérequis

- Consulter [la préparation du laboratoire](../../docs/PREREQUIS.md) et la [fiche de sécurité](../../docs/SECURITE.md).
- Se placer dans le projet modèle indiqué par le formateur ; disposer de la clé SSH **publique**.
- Faire valider l'abonnement Azure ou le pool/VMID Proxmox avant tout `apply` ou `destroy`.

## Travail demandé

Compléter initialization { ip_config { ipv4 { address="dhcp" } } user_account { username="debian" keys=[trimspace(file(var.ssh_public_key_path))] } }. Vérifier le DHCP, relever l’adresse via l’interface/agent et se connecter en SSH.

### Séquence de contrôle

```bash
terraform fmt -check
terraform validate
terraform plan
# Après validation explicite du plan et de la cible :
terraform apply
terraform state list
```

> Les commandes s'exécutent dans un répertoire Terraform initialisé. Pour TP01, `terraform fmt` peut être utilisé pour corriger les fichiers avant le contrôle.

## Questions de réflexion / incident

Pourquoi une clé publique plutôt qu’un mot de passe ? Le guest agent est-il opérationnel ?

## Preuves à remettre

- Fichiers `.tf` et `.tfvars.example` **sans secrets**, versionnés si demandé.
- Résumé des changements annoncés par `terraform plan`.
- Capture ou sortie de vérification (sans adresse/clé sensible ni token).
- Deux phrases expliquant la validation de l'objectif et les limites constatées.

## Critères de réussite

SSH par clé fonctionne; un cloud-init est appliqué au premier démarrage; aucune clé privée n’est dans Git.

## Nettoyage

Vérifier la cible, sauvegarder les preuves, puis demander l'accord du formateur avant une éventuelle destruction : `terraform plan -destroy` suivi, seulement si autorisé, de `terraform destroy`.
